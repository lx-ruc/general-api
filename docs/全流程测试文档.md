# token 中转站 · 全流程测试文档

> 按顺序执行即可完整走通「平台 → 公司 → 员工 → API 调用 → 计费 → 审批」全链路。
> 每一步都有 **操作**、**预期结果**、必要时附 **核验命令**。
>
> - 服务地址：`http://localhost:8080`（管理台直接浏览器打开）
> - 当前已配置渠道：DeepSeek、智谱 GLM（真实密钥，已测通）；通义千问（未配 key）
> - 真实调用会产生**极少量费用**（每次约 ¥0.0002 ~ ¥0.002）；想零成本可用 `mock-chat` 模型代替（需先 `python3 /tmp/tg_mock_upstream.py` 启动本地 mock）

## 5. API 调用验证（真实厂商）

> 以下命令把 `<SK>` 替换成 4.2 保存的密钥。

### 5.1 模型列表
```bash
curl -s http://localhost:8080/v1/models \
  -H "Authorization: Bearer <SK>" | python3 -m json.tool
```
**预期**：`data` 数组恰好含 3 个授权模型。

### 5.2 非流式调用（DeepSeek）
```bash
curl -s http://localhost:8080/v1/chat/completions \
  -H "Authorization: Bearer <SK>" -H "Content-Type: application/json" \
  -d '{"model":"deepseek-chat","messages":[{"role":"user","content":"一句话介绍你自己"}],"max_tokens":60}' \
  | python3 -m json.tool
```
**预期**：HTTP 200，返回 DeepSeek 正常回答，`usage` 字段有 `prompt_tokens` / `completion_tokens`。

### 5.3 流式调用（GLM，思考模型）
```bash
curl -sN http://localhost:8080/v1/chat/completions \
  -H "Authorization: Bearer <SK>" -H "Content-Type: application/json" \
  -d '{"model":"glm-4.5","stream":true,"messages":[{"role":"user","content":"只回复两个字：好的"}]}' \
  | tail -5
```
**预期**：逐块输出 SSE 事件（GLM 会先输出 `reasoning_content` 思考块再输出 `content`），倒数第二块带 `usage`，最后 `data: [DONE]`。
**注意**：不要用 `head` 截断管道，否则收不到末尾 usage（网关与客户端都会正常，只是看不到结尾）。

### 5.4 Python SDK（openai 官方 SDK 直连中转站）
```python
from openai import OpenAI

client = OpenAI(api_key="<SK>", base_url="http://localhost:8080/v1")

resp = client.chat.completions.create(
    model="glm-4-flash",                      # 免费模型
    messages=[{"role": "user", "content": "回复：OK"}],
)
print(resp.choices[0].message.content)
print(resp.usage)
```
**预期**：打印模型回复和 usage。任何支持自定义 `base_url` 的工具（Cherry Studio、沉浸式翻译等）同理接入。

## 6. 计量计费核验

### 6.1 界面核验（三级看板）
1. 员工端「我的用量」：今日请求 ≥ 3，调用记录里每笔有 tokens 和成本
2. 退出 → `liance_admin` 登录「公司看板」：公司池已消耗增长，「员工消耗 Top」出现 tester01
3. 退出 → `admin` 登录「数据看板」：今日请求数包含以上调用，「公司消耗 Top」出现联测科技

### 6.2 数据库核验（可选，在项目根目录执行）
```bash
# 最近 5 笔计费（tokens、单价快照、成本）
sqlite3 data/token_.db "SELECT model_name, prompt_tokens, completion_tokens,
  input_price, output_price, cost, status FROM usage_logs ORDER BY id DESC LIMIT 5;"

# 员工与公司双层余额（应相等增长）
sqlite3 data/token_.db "SELECT '员工', quota_limit, quota_used FROM users WHERE username='tester01';
                        SELECT '公司', quota_limit, quota_used FROM orgs WHERE name='联测科技';"
```
**预期**：
- 每笔 `cost = ceil(prompt×输入单价 + completion×输出单价) ÷ 1000000`
- 例：deepseek-chat 8入/27出 → `(8×2000000 + 27×8000000)/1000000 = 232` 点
- 员工 `quota_used` 与公司 `quota_used` 增量一致

## 7. 异常与边界场景

### 7.1 未授权模型 → 403
```bash
curl -s http://localhost:8080/v1/chat/completions \
  -H "Authorization: Bearer <SK>" -H "Content-Type: application/json" \
  -d '{"model":"qwen-max","messages":[{"role":"user","content":"hi"}]}'
```
**预期**：`403`，`"code": "model_not_allowed"`，提示联系公司管理员。

### 7.2 无效密钥 → 401
```bash
curl -s http://localhost:8080/v1/models -H "Authorization: Bearer sk-invalid0000000000000000000000000000000000000000"
```
**预期**：`401 invalid_api_key`。

### 7.3 额度耗尽 → 429（审批闭环）
1. `liance_admin` 登录 →「员工管理」→ tester01 行「额度」→ 追加 `**-2000000**`（负数回收，剩余额度归 0）
2. 员工用 `<SK>` 再调一次 5.2 的命令

**预期**：`429 insufficient_quota`，消息为 `employee quota exceeded, please contact your company admin`。

3. **发起申请**：tester01 登录 →「额度申请」→ 申请 `1000000` 点（¥1），理由随意 → 提交
4. **审批**：`liance_admin` 登录 → 左侧「额度申请」（**注意侧栏该菜单出现铜橙色角标**）→「批准」

**预期**：申请变「已批准」；tester01 额度页余额恢复 ¥1；再执行 5.2 调用恢复 200。

### 7.4 密钥禁用 → 401（运维）
1. `liance_admin` →「密钥一览」→ 找到 tester01 的密钥 →「禁用」
2. 员工再调用 5.1

**预期**：`401 invalid_api_key`。
3. 测完记得「启用」恢复。

### 7.5 限流 → 429（可选）
```bash
for i in $(seq 1 15); do
  curl -s -o /dev/null -w "%{http_code} " http://localhost:8080/v1/chat/completions \
    -H "Authorization: Bearer <SK>" -H "Content-Type: application/json" \
    -d '{"model":"glm-4-flash","messages":[{"role":"user","content":"hi"}]}' &
done; wait; echo
```
**预期**：默认 60 次/分钟 + 突发 10，15 个并发里出现若干 `429`，其余 `200`。

## 附录：错误码速查

| 状态码 | code | 含义 | 处理 |
|---|---|---|---|
| 401 | invalid_api_key | 密钥错误/被禁用/已过期 | 检查 Bearer，找管理员启停 |
| 403 | model_not_allowed | 模型未授权 | 公司管理员「模型授权」勾选 |
| 429 | insufficient_quota | 员工或公司额度耗尽 | 发起额度申请 / 平台追加 |
| 429 | rate_limit_error | 触发限流（60 RPM/密钥） | 稍后重试或联系平台调额 |
| 503 | service_unavailable | 无可用渠道 | 渠道未启用/未配密钥 |
| 502 | upstream_error | 全部渠道失败 | 看「调用日志」错误详情 |
